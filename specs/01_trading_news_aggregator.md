## Исходное описание (от пользователя)

Программа берёт название указанной компании и собирает:

1. **Новости** с определённой даты.
   - 1.1. Глобальная дата начала (с возможностью переопределить для конкретной компании).
   - 1.2. При ежедневном использовании — попытка найти новости 1 раз в час.
   - 1.3. Список источников строго определён.
   - 1.4. Каждую новость анализируем — определяем новостной фон.
   - 1.5. Создаём папку с именем компании:
     - 1.5.1. `news/` — иерархия `Компания/Год/Год_Месяц(MM)/`.
     - 1.5.2. `affiliate/persons.csv` — таблица аффилированных лиц.
       Поля: `person, status, brand, pos_freq, neg_freq, zero_freq, total_freq`
       (`total_freq` пересчитывается как сумма; частоты пересчитываются при каждом изменении).
     - 1.5.3. `news_list/data.xlsx` — таблица новостей.
       Поля: `date (yyyy_mm_dd), headline, persons (через запятую), mood (pos/neutral/neg)`.
   - 1.6. Анализ новости:
     - 1.6.1. Тональность (положительный/нейтральный/отрицательный).
     - 1.6.2. Упоминание аффилированных лиц → попытка определить:
       - 1.6.2.1. Статус (CEO, CFO, совет директоров, топ-менеджмент, руководители брендов,
         IR-директор, PR-директор, крупные акционеры, отраслевые эксперты, бывшие сотрудники,
         аналитики, блогеры, журналисты, Telegram-каналы, эксперты FMCG, консультанты,
         депутаты/чиновники, регулярно комментирующие X5).
       - 1.6.2.2. С каким брендом он связан.
   - 1.7. Сохранение новости в Obsidian:
     - 1.7.1. Имя файла `yyyy_mm_dd_Краткий_заголовок_порядковый_номер.md`.
     - 1.7.2. В шапке указываем аффилированных лиц.

2. **MVP — только X5.** Дальше добавим другие компании после успешного тестирования.

3. **Дальнейшие этапы:**
   - новости из Telegram-каналов;
   - финансовая отчётность;
   - торговые рекомендации от инвесткомпаний;
   - биржевые котировки.

4. По мере разработки — фронтэнд и бэкенд.

## Альтернативные подходы

### A) Python + SQLite + генерируемые отчёты ⭐ (рекомендую)
- **Стек:** Python 3.12, `feedparser`/`httpx`+`selectolax`, `sqlite3`, Anthropic API,
  `openpyxl`, шаблоны MD
- **Структура:** `sources.yaml` → `fetcher.py` (час) → `analyzer.py` (LLM) →
  `db.sqlite` (истина) → `reporter.py` (Excel + Obsidian MD)
- **Запуск:** Windows Task Scheduler раз в час
- **Усилие:** S-M (1-2 недели до рабочего MVP по X5)
- **Плюсы:** не падает от Excel-блокировок, легко расширять, агрегаты — SQL
- **Минусы:** нужно настроить Task Scheduler

### B) Bash-точно-как-в-спеке (CSV/Excel/MD как истина, без БД)
- **Усилие:** S
- **Плюсы:** буквально как описано
- **Минусы:** Excel ломается при параллельной записи; пересчёт частот замедляется
  через 6 месяцев; миграции таблиц — вручную
- Не рекомендую

### C) n8n / Make + Google Sheets (no-code)
- **Плюсы:** визуально, без кода
- **Минусы:** упрёшься на NER-задачах, Telegram, котировках, бэке
- Не подходит для дальнейших этапов

**Какой подход: A / B / C?**
A

## Решено / зафиксировано

**Архитектура:**
- Подход **A**: Python 3.12 + SQLite (источник истины) + генерируемые отчёты (Excel + Obsidian MD).
- Локальный CLI. Без CI/CD. Запуск через Windows Task Scheduler раз в час.
- Конфиг — `config.yaml` (глобальная дата начала, переопределения по компаниям, ключи API).

**Анализ:**
- LLM — **GPT-5 mini** через OpenAI API на старте. Локальную модель оценим позже.
- API-ключ в `.env` как `OPENAI_API_KEY`. Библиотека — `openai` (Python SDK).
- Тональность — **с точки зрения PR** (репутация бренда), не торговая.
- NER аффилированных лиц — на основе seed-списка (см. P4 в спеке), LLM **дополняет**.

**Источники (9 шт.):**
Interfax, РБК, Ведомости, Коммерсантъ, e-disclosure, X5 IR, MOEX, Финам, Forbes.

**MVP — первый шаг (1-я неделя):**
Парсинг **одного источника** — сайт X5 IR (`x5.ru/ru/investors`) с ручной валидацией
результатов перед тем, как подключать LLM и остальные источники.

**Seed-список персон X5** (13 шт.) — см. P4 выше, переносится в `seed/x5_persons.csv`.

**Хранение:**
- Истина: `data/db.sqlite` (таблицы: `companies`, `sources`, `news`, `persons`, `news_persons`).
- Read-only представления, генерируемые `reporter.py`:
  - `output/X5/news/2026/2026_05/*.md` — Obsidian-файлы (`yyyy_mm_dd_заголовок_NN.md`).
  - `output/X5/affiliate/persons.csv` — таблица персон (агрегаты пересчитываются).
  - `output/X5/news_list/data.xlsx` — таблица новостей.

**Глобальная дата начала на период тестов:** `2026-05-01`
(в `config.yaml` → `global.start_date`). Меняем когда выйдем из тестов.

**Автоматический режим — выключен по умолчанию:**
- Скрипт **не** регистрируется в Windows Task Scheduler автоматически.
- На MVP запускается только вручную: `python -m src cycle --company X5`.
- В `config.yaml` есть глобальный флаг `auto_run: false` (по умолчанию).
- Документацию «как включить автозапуск раз в час» оставляем в README,
  но действий по регистрации задачи не делаем.
- Пользователь явно скажет, когда переводить в автоматический режим.

**Векторная БД — решение:**
- На MVP **не используем**. Sentiment и NER не требуют эмбеддингов; на одном
  источнике (X5 IR) дублей нет.
- Архитектуру оставляем расширяемой: `news.body` хранит полный текст; при
  необходимости добавим таблицу `news_embeddings` и расширение **sqlite-vec**
  (без отдельной БД, всё остаётся в `data/db.sqlite`).
- Триггер для отдельной спеки (`specs/03_*` или позже): ≥3 источника и очевидные
  дубли, ИЛИ ≥1000 новостей и сложно искать вручную, ИЛИ нужна фича «похожие
  новости» во фронте.
- Use cases когда заведём: дедуп новостей между источниками, поиск похожих,
  кластеризация по темам, RAG для исторического анализа.
